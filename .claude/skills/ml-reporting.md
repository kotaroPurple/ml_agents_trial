# ml-reporting

このSkillは `reporter` と `ml-reviewer` が参照する。目的は、スライドが単なる結果一覧ではなく、評価の前提と限界を含む説明可能な資料になること。

## Required Slide Content

生成資料には以下を含める。

- 目的: 何を予測・分類する実験か。
- データ概要: 行数、列数、ターゲット、欠損、タスク種別。
- 前処理: 主要な特徴量変換、欠損処理、カテゴリ処理。
- 評価方法: train/test分割、主要指標、best model選定基準。
- モデル比較: 比較対象モデルと主要指標。
- ベストモデル: 選定理由と代表的なプロット。
- 限界: ホールドアウトのみ、データリーク未検証、外部検証なしなど該当するもの。
- 次アクション: 追加検証、特徴量改善、交差検証、業務指標との接続。

## Writing Rules

- 結論は指標と根拠に紐づけて書く。
- 「高精度」「有効」などの断定は、比較対象と評価条件がある場合に限る。
- 評価条件が弱い場合は、意思決定前に必要な追加検証を明記する。
- 図表がない場合は無理に参照せず、未生成であることを短く示す。

## Marp Rules

- `src/ml_agents_trial/presentation/templates/base.marp.md` のプレースホルダーは全て置換する。
- 画像は `artifacts/presentation/images/` にコピーし、スライドからは相対パスで参照する。
- 表は列数を増やしすぎず、主要指標を優先する。

## Reviewer Pass Criteria

`ml-reviewer` は以下を満たせばPASSにする。

- 目的、評価方法、限界、次アクションが資料データまたはスライドに含まれる。
- best modelの主張が `comparison.json` の指標と一致している。
- 評価条件を超えた断定がない。
