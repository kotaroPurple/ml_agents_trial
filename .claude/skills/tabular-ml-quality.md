# tabular-ml-quality

このSkillは `feature-engineer`, `model-architect`, `evaluator`, `ml-reviewer` が参照する。目的は、AI生成コードが「動く」だけでなく、ML評価として信頼できる最低条件を満たすようにすること。

## Core Rules

- ターゲット列は特徴量変換、欠損補完、エンコーディング、スケーリングの対象にしない。
- テストデータ由来の統計量を、学習前処理や特徴量選択に使わない。
- 欠損補完、カテゴリエンコード、スケーリングなどのfitが必要な処理は、可能な限り `sklearn Pipeline` / `ColumnTransformer` に寄せる。
- `build_features(df, target)` が単純なDataFrame変換として残る場合でも、全データ由来のターゲット統計やテスト情報を使う変換は禁止する。
- 交互作用特徴量や対数変換は、EDA上の根拠と列名を説明できるものに限定する。

## Model Selection

- 回帰では少なくとも線形系ベースラインと非線形モデルを比較する。
- 分類では少なくとも単純ベースライン、線形系モデル、木系モデルを比較する。
- ベースラインより複雑なモデルを採用する場合は、改善した主要指標を明示する。
- LightGBMを使う場合は `verbose=-1` を設定し、固定乱数を指定できるモデルには `random_state=42` を設定する。

## Metrics

- 回帰の主要指標は `rmse` とし、`mae`, `r2`, `mape` も可能な範囲で併記する。
- 分類の主要指標は `f1` または `accuracy` とし、不均衡が疑われる場合は `f1` を優先する。
- 分類でAUCを出す場合は、クラス数と予測スコアの扱いが妥当な場合に限る。
- 指標計算は `ml_agents_trial.core.metrics` の関数を使い、独自実装しない。

## Evaluation Checks

- 学習指標とテスト指標を比較し、過学習が疑われる場合はレポートに残す。
- ホールドアウト分割のみの場合、その限界を資料に明記する。
- 分類では可能な限り層化分割を検討する。時系列データではランダム分割を避ける。
- best modelの選定基準はタスク種別ごとに固定する。回帰は `rmse` 最小、分類は `f1` 優先、なければ `accuracy` 最大。

## Reviewer Pass Criteria

`ml-reviewer` は以下を満たせばPASSにする。

- ターゲットリークが見当たらない。
- タスク種別とモデル、指標、best model選定基準が一致している。
- ベースライン比較がある、またはない理由が明記されている。
- 評価の限界がreporterに渡るartifactまたは資料に残る。
